# Financial Markets – Session 4: Information Management, AI Workflows & Bond Returns

## 1. Session Overview

Session 4 followed a different structure from the previous classes.

Instead of beginning directly with financial theory, the first major block focused on a broader question:

> **How should students manage information in an AI-driven world?**

The class argued that the relevant question is increasingly not:

> _Which AI should I use?_

but:

> **How is my information organized?**

Students were introduced to a workflow based on:

- Markdown files;
    
- Obsidian;
    
- local folders;
    
- linked notes;
    
- structured information;
    
- AI agents working directly over those files.
    

The second part of the class returned to fixed income and reviewed:

- bond pricing;
    
- yield to maturity;
    
- premium, par and discount bonds;
    
- Holding Period Return;
    
- reinvestment of coupons;
    
- the effect of interest-rate changes on realized returns.
    

The main message connecting both parts was the same:

> **Tools become powerful when the underlying structure is good.**

---

# 2. From “Which AI?” to “How Do You Manage Your Data?”

The class began with what the professor described as the **wrong question**:

> Which AI would you use?

The more important question is:

> **How do you organize your data?**

Different AI models may change rapidly.

The information accumulated during your studies and professional life should therefore not depend entirely on one particular platform.

The objective is to create an information structure that can later be used by many different tools.

This is why the class focused on:

- plain-text files;
    
- Markdown;
    
- local folders;
    
- reusable information;
    
- linked knowledge.
    

---

# 3. Obsidian as an Information Layer

Students were asked to install and open **Obsidian**.

The initial exercise was deliberately simple:

1. create a folder called **Financial Markets**;
    
2. open that folder in Obsidian;
    
3. create several notes;
    
4. connect those notes.
    

The point was not to learn every feature of Obsidian.

Instead, students were shown that Obsidian is fundamentally a way of managing ordinary files.

These files are primarily:

> **Markdown (`.md`) files**

The class transcriptions distributed during the course are also Markdown files.

---

# 4. Markdown: “Plain Text with Vitamins”

Markdown was described intuitively as:

> **plain text with vitamins**

It remains readable as ordinary text while allowing simple structure.

Examples introduced included:

### Headings

```text
# Main title
## Second-level title
```

### Lists

```text
- Item 1
- Item 2
```

### Bold text

```text
**Important**
```

Markdown can also contain:

- tables;
    
- formulas;
    
- links;
    
- images;
    
- structured metadata.
    

## An important practical point is that students have probably already seen Markdown without realizing it, because many AI systems naturally generate responses using Markdown-style formatting.

# 5. Connecting Information

One of Obsidian's central features is the ability to create links between notes.

For example:

```text
[[First Note]]
```

creates a connection to another note.

If the note does not yet exist, it can be created directly from that link.

The resulting system is therefore more than a collection of isolated documents.

It can become a **knowledge graph**.

Conceptually:

Information→Notes→Connections→Knowledge StructureInformation \rightarrow Notes \rightarrow Connections \rightarrow Knowledge\ Structure

The important point is not the software itself.

The important point is learning to structure information so that ideas can be:

- found;
    
- connected;
    
- reused;
    
- expanded.
    

---

# 6. Local Files and Control of Information

The class also emphasized the value of working with a **local information system**.

The files demonstrated during class were stored locally rather than existing only inside an online platform.

This provides:

- portability;
    
- control;
    
- independence from one AI provider;
    
- easier reuse by different tools.
    

The broader principle was:

> **Your information should remain yours, while AI tools can operate on top of it.**

---

# 7. Adding an AI Workspace

The next step was to connect the same folder to an AI-enabled workspace or **harness**.

The basic logic is:

$$\text{Local Folder} + \text{Structured Markdown} + \text{AI Agent} = \text{Active Workspace}$$

Instead of asking a chatbot isolated questions, the agent can work directly with an organized project.

The class demonstrated how the agent could:

- inspect files;
    
- modify notes;
    
- create new documents;
    
- reorganize information;
    
- generate reports;
    
- create web pages.
    

The important lesson was that the quality of the workflow depends heavily on the quality of the context provided to the system.

---

# 8. Context Before Execution

The professor repeatedly instructed the AI:

> **Do not do anything yet.**

This illustrated an important working principle.

Before allowing an AI agent to execute actions:

1. explain the context;
    
2. define the objective;
    
3. specify the structure;
    
4. clarify constraints;
    
5. only then ask it to act.
    

This can be called **bootstrapping the context**.

The system progressively learned:

- that the user was teaching finance;
    
- that the output should be in English;
    
- that the project involved Obsidian;
    
- what files were relevant;
    
- what the immediate objective was.
    

Only after this context had been established was the AI asked to create or modify material.

---

# 9. Specification-Driven Work

The class contrasted two approaches.

### Weak approach

> “Create a complete website.”

### Better approach

Break the project into smaller, explicit steps.

For example:

1. define the objective;
    
2. create the structure;
    
3. define folders;
    
4. create content;
    
5. check the result;
    
6. generate the final artifact.
    

The professor referred to this as closer to **spec-driven work** than simply “vibe coding.”

The broader idea is:

> **Plan first, execute second.**

This applies not only to programming but also to research, finance, writing and information management.

---

# 10. Human Control Remains Essential

The class also demonstrated a critical limitation of AI.

When the system generated information about the Federal Reserve, it produced outdated or incorrect information.

The professor immediately corrected it and instructed the system to review the material.

This provided a live example of an important principle:

> **The work produced by AI is still the user's responsibility.**

AI can work extremely quickly.

But speed does not remove the need for:

- verification;
    
- judgment;
    
- supervision.
    

The user must remain responsible for deciding whether the information is correct.

---

# 11. AI as an Information Transformer

Once information had been organized in Markdown, the class demonstrated that the same content could be transformed into other outputs.

The agent was asked to produce:

- structured notes;
    
- a report;
    
- a DOCX document;
    
- a simple webpage.
    

The underlying idea is:

Structured Information→Multiple OutputsStructured\ Information \rightarrow Multiple\ Outputs

The expensive part intellectually is therefore not necessarily formatting the final product.

It is creating and verifying the underlying information.

Once that structure is good, AI can transform it rapidly into different formats.

---

# 12. Information Management as a Core Skill

One of the strongest messages of the session was:

> **You should be extremely fast at finding your own information.**

Students should not spend significant time looking for:

- a file;
    
- a slide deck;
    
- an exercise;
    
- a note;
    
- a previous class.
    

Information management becomes increasingly important when AI systems themselves operate at very high speed.

If the human side of the workflow is disorganized, information retrieval becomes the bottleneck.

Conceptually:

$$\text{AI Speed}\uparrow$$

means that:

Human OrganizationHuman\ Organization

becomes increasingly important.

---

# 13. AI and Education

The professor encouraged students to experiment with these tools rather than simply watch demonstrations.

The analogy used was learning to drive.

When someone first starts driving:

- everything feels difficult;
    
- actions are slow;
    
- attention is consumed by basic operations.
    

With practice, those actions become natural.

The same applies to AI tools.

Students do not need to become software engineers.

But they should understand what modern tools can do and how to use them responsibly.

The message was not:

> Use AI to avoid working.

It was:

> **Use AI to learn and work better.**

# 15. What Is the Dot Plot?

The **dot plot** was introduced as an important Federal Reserve communication tool.

Each dot represents an individual policymaker's view of an appropriate level of interest rates at different future horizons.

Conceptually, it provides information about policymakers' expectations for:

- the current year;
    
- future years;
    
- the longer run.
    

The dot plot does not mechanically determine future policy.

Instead, it provides a window into the distribution of views inside the Federal Reserve.

This makes it relevant for financial markets because investors continuously compare:

Market ExpectationsMarket\ Expectations

with:

Central Bank ExpectationsCentral\ Bank\ Expectations

The difference between the two can move asset prices.

---

# 16. The Federal Reserve Is a System

Another concept introduced was that the Federal Reserve should not be understood simply as one institution in Washington.

The system includes:

- the Board of Governors;
    
- twelve regional Federal Reserve Banks;
    
- the Federal Open Market Committee (FOMC).
    

The class used the AI workflow to construct notes on these different components.

The objective was not to memorize every institutional detail immediately.

It was to understand that monetary-policy decisions emerge from a **system of institutions and policymakers** rather than from one person alone.

> **There was no fundamentally new mathematics.**

The purpose was to become increasingly comfortable using it.

---

# 18. Four-Year Coupon Bond Example

The class considered a four-year bond with:

$$\text{Face Value} = 1,000 \qquad \text{Coupon} = 80 \qquad \text{Coupon Rate} = 8\%$$

If the market discount rate is also:

$$r = 8\%$$

then:

$$\text{Coupon Rate} = \text{Market Yield}$$

and therefore:

$$\boxed{\text{Price} = 1,000}$$

The bond trades at **par**.

---

# 19. Bond Pricing

The price is obtained by discounting every future cash flow:

$$P = \frac{80}{1.08} + \frac{80}{1.08^2} + \frac{80}{1.08^3} + \frac{1,080}{1.08^4}$$

which gives:

$$P = 1,000$$

Again:

$$\boxed{\text{Price} = \text{Present Value of Future Cash Flows}}$$

This remains the central valuation principle.

---

# 20. Reinvesting Coupons

The class then introduced an important issue that does not exist in a zero-coupon bond:

> **What happens to coupon payments after they are received?**

Suppose every €80 coupon is reinvested at 8%.

The first coupon can compound for three additional years:

$\$80(1.08)^3$$

The second coupon compounds for two years:

$\$80(1.08)^2$$

The third for one year:

80(1.08)80(1.08)

The final payment is received at maturity.

Adding these values gives the terminal wealth of the investment.

---

# 21. Holding Period Return

Once the terminal wealth is known, the annualized Holding Period Return can be obtained through the same formula used throughout the course:

$$FV = PV(1+r)^t$$

Solving for $r$:

$$\boxed{r = \left( \frac{FV}{PV} \right)^{1/t} - 1}$$

If:

- the bond is purchased at a yield of 8%;
    
- all coupons are reinvested at 8%;
    
- the investor holds the bond to maturity;
    

then the realized annual return is also:

$$\boxed{8\%}$$

This is an important result.

---

# 22. Reinvestment Risk

What happens if coupons cannot be reinvested at 8%?

If the reinvestment rate is lower:

$$\text{Reinvestment Rate}\downarrow \;\Rightarrow\; \text{Terminal Wealth}\downarrow$$

and therefore:

$$\text{Realized Return}\downarrow$$

If coupons can be reinvested at a higher rate:

$$\text{Reinvestment Rate}\uparrow \;\Rightarrow\; \text{Realized Return}\uparrow$$

This introduces:

> **reinvestment risk**

Coupon bonds create uncertainty not only because their market price can change, but also because future coupons may need to be reinvested at unknown future rates.

---

# 23. Yield to Maturity Is Not Automatically the Realized Return

This produces an important distinction.

**Yield to Maturity (YTM)** is a rate implied by the bond's current price and promised cash flows.

But actually earning that yield depends on assumptions.

For a coupon bond, one important assumption is that coupons can be reinvested at the relevant rate.

Therefore:

$$\text{YTM} \neq \text{Automatically Realized Return}$$

The realized outcome depends on what actually happens during the investment period.

---

# 24. Interest Rates and the Bond Price

The central mantra returned once again:

$$\boxed{\text{Rates}\uparrow \;\Rightarrow\; \text{Bond Prices}\downarrow} \qquad \boxed{\text{Rates}\downarrow \;\Rightarrow\; \text{Bond Prices}\uparrow}$$

If market rates fall from 8% to 7%, an existing bond paying an 8% coupon becomes more valuable.

Its market price rises.

If market rates rise above 8%, its price falls.

This relationship remains fundamental for understanding fixed income.

---

# 25. Two Interest-Rate Effects

Coupon bonds therefore expose investors to two effects when rates change.

### Price effect

$$\text{Rates}\downarrow \;\Rightarrow\; \text{Bond Price}\uparrow$$

### Reinvestment effect

$$\text{Rates}\downarrow \;\Rightarrow\; \text{Coupon Reinvestment Return}\downarrow$$

These effects move in opposite directions.

This is one of the reasons fixed-income analysis becomes more interesting once coupon bonds are introduced.

---

# 26. The Mathematics Is Still the Same

The professor closed the technical section with an important observation.

Despite discussing:

- bonds;
    
- coupons;
    
- HPR;
    
- reinvestment;
    
- market yields;
    

the underlying mathematics was still the same Time Value of Money framework introduced earlier:

$$\boxed{PV = \frac{FV}{(1+r)^t}}$$

Most of fixed income can be understood by repeatedly applying this logic to different cash flows.

# Final Takeaway

Session 4 connected two apparently different subjects: **AI and fixed income**.

But the underlying principle was similar.

In fixed income, the value of a bond depends on how its cash flows are structured.

In an AI workflow, the value of the tool depends heavily on how the information is structured.

In both cases:

> **Structure determines what can be done afterwards.**

For finance:

Cash Flows+Discount Rate→ValueCash\ Flows + Discount\ Rate \rightarrow Value

For AI-assisted knowledge work:

Organized Information+Context+AI→Useful OutputOrganized\ Information + Context + AI \rightarrow Useful\ Output

The technology may change rapidly.

The ability to **organize information, understand the underlying logic and verify the result** will remain valuable.
